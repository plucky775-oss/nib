# Nib — 나의 글씨, 더 단정하게

아이패드·Apple Pencil 중심으로 만든 웹 노트 앱입니다. 저장소: https://github.com/plucky775-oss/nib . 외부 서비스 키 없이 필기·획 보정·저장·글꼴 선택을 사용할 수 있습니다. **실제 iPad/Pencil 및 실제 Gemini 인식은 아직 검증하지 않았습니다.**

## 두 모드의 정확한 범위

### 1. 내 필체 다듬기
- Pointer Events 기반 원본 획 수집, 획의 작은 떨림을 완화하는 국소 필터.
- 강도 조절, 원본/보정본 비교, 펜·색상·굵기, 획 지우개, 실행 취소/재실행.
- 글자의 의미나 구조를 이해하지 않습니다. 글자 모양을 새로 쓰거나 자간·줄맞춤을 자동 교정하지 않습니다.
- 필압 데이터는 기록하지만 현재 렌더링은 일정한 굵기입니다. 완전한 네이티브 PencilKit 경험으로 설명하면 안 됩니다.

### 2. 예쁜 필체로 변환
- 원본 획을 PNG로 만들고, 사용자가 전송에 동의한 뒤 직접 변환을 실행하거나 자동 변환을 켰을 때만 서버로 보냅니다.
- 서버는 Google Gemini `gemini-3.1-flash-lite`로 글자만 인식합니다. 이미지를 새로 생성하지 않습니다.
- 인식 결과를 무료 한글 글씨체로 표시하며 사용자가 확인·수정할 수 있습니다. 원본 획은 별도로 보존합니다.
- 키/접근코드 미설정 시 서버는 503을 반환하며 UI에는 `AI 인식 · 연결 전`이 표시됩니다. 샘플을 인식한 것처럼 보여주지 않습니다.
- 키 연결 전에도 별도 키보드 편집창에서 입력한 텍스트를 선택한 글씨체로 볼 수 있습니다. 기본 필기 종이는 텍스트 입력칸이 아니며 OS Scribble 사용을 유도하지 않습니다.
- 한글 악필 정확도, 수식·도형·배치 재현은 보장하지 않습니다. [판독불가]와 인식 오류를 직접 수정해야 합니다.

## 기본 기능

- IndexedDB에 자동 저장되는 다중 노트(기기·브라우저별). 저장을 직렬화하고, 다른 탭에서 바뀐 노트를 이전 버전으로 덮어쓰지 않도록 충돌을 감지합니다. 충돌 시 현 내용을 백업하고 새로고침하세요.
- 한 노트에 원본 획과 텍스트 모드를 각각 보존.
- JSON 전체 백업 및 기존 내용을 덮어쓰지 않는 복사본 가져오기. 큰 백업은 24MB 단위 파일로 나눕니다. 모든 조각을 보관하세요.
- 현재 모드 PNG 내보내기 및 브라우저 인쇄/PDF. PNG는 한 페이지(900×1200)이며 긴 텍스트는 잘릴 수 있습니다. 전체 복원용 형식은 JSON입니다.
- 노트당 최대 5,000획/300,000점, 텍스트 50,000자, 노트 100개. 가져오기 파일 최대25MB.
- 기본 손가락 필기는 꺼져 있고 사용자가 켤 수 있습니다. Pencil palm rejection/기기별 스크롤은 실기 확인이 필요합니다.
- PWA manifest와 서비스워커. 최초 온라인 방문 뒤 캐시된 정적 파일을 오프라인 사용. 아직 내려받지 않은 글꼴은 오프라인에서 표시되지 않을 수 있습니다.

## 실행·검증

런타임 의존성은 없습니다. Node.js 22 이상을 권장합니다.

```sh
npm run check
npm test
npm run build
```

`dist/`는 정적 프런트엔드입니다. 서버를 갖춘 환경에서 미리보기하세요. `file://`로 직접 여는 것은 ES modules/IndexedDB/서비스워커 동작 보장이 없습니다. Vercel은 `vercel.json`의 `buildCommand`와 `outputDirectory`를 사용합니다. **GitHub Pages처럼 정적 파일만 배포하면 `/api/*` 인식은 동작하지 않습니다.**

`api/`는 서버 코드이며 정적 `dist/`에 포함하지 않습니다. 사용자가 `plucky775-oss/nib` 저장소를 생성했습니다. 이 작업의 원격 push/배포는 아직 하지 않았습니다.

## 나중에 AI 연결하기

관리자가 배포 플랫폼의 서버 환경변수로 설정합니다. 브라우저 번들, GitHub, 입력란에 API 키를 넣지 마세요. 키 생성·연결은 소유자의 별도 승인 이후에만 수행합니다.

- `Gemini_API_Key`: 사용자가 지정한 Google Gemini 서버 키 환경변수 이름(대소문자 구분). 기존 `GEMINI_API_KEY`도 지원하지만 둘 다 있으면 `Gemini_API_Key`를 우선합니다.
- `NIB_ACCESS_TOKEN`: 관리자만 아는 별도 앱 이용 코드, 최소4자(임시 4자리 지원, 긴 무작위 코드 권장). 공개 URL의 무단 API 사용을 막기 위한 값이며 Gemini API 키와 달라야 합니다.

둘 다 설정되어야 `GET /api/status`가 `{configured:true}`를 반환합니다. 값 자체는 반환하지 않습니다. 사용자는 변환 창의 이용코드 칸에 **앱 이용 코드만** 입력합니다. 앱은 이 코드를 로컬스토리지·IndexedDB에 저장하지 않고 페이지 메모리에서만 사용합니다.

- 직접 인식을 실행하거나 동의한 자동 변환이 진행될 때 현재 노트의 **원본 필기 이미지**만 서버를 거쳐 Google로 전송됩니다. 노트 제목·다른 노트는 보내지 않습니다.
- API 사용료는 연결된 Gemini 계정의 정책·사용량을 따릅니다. 기능 사용 전 전송과 비용 안내가 표시됩니다.
- 자동 재시도 없음, 프런트 중복요청 방지, 서버 시간제한·PNG 형식/크기 제한, 출력완료 상태 확인.
- 잘못된 이용 코드 입력은 IP별 10분에 5회까지 허용하고 이후 차단합니다. 이 제한 역시 서버 프로세스 메모리 기반으로 재시작·여러 인스턴스·IP 변경에 대한 전역 방어를 보장하지 않습니다. 4자리 코드는 추측이 쉬운 임시 보호이며 로그인 또는 강한 코드로 교체해야 합니다.
- 서버의 IP별 1분6회/동시1회 제한은 **프로세스 메모리 기반 보조 제한**입니다. 여러 서버 인스턴스 전체의 사용량 상한이나 과금 차단을 보장하지 않습니다. 공개 다중사용자 서비스에는 지속 저장형 레이트리미트·개별 인증·사용량 모니터링이 필요합니다. 이용코드를 공유하지 말고 제공자 측 사용량 한도도 확인하세요.
- 서버는 이미지·인식문·키를 로그로 남기지 않습니다. 호스팅 제공자의 요청 로그/Google 데이터 정책은 별도입니다.

## 무료 글꼴

나눔손글씨 펜, 나눔손글씨 붓, 개구, 감자꽃, 푸어스토리 5종의 공식 Google Fonts TTF와 원문 SIL OFL 라이선스를 포함했습니다. 라이선스·출처·해시는 [public/fonts/README.md](public/fonts/README.md), [fonts.json](public/fonts/fonts.json)에 있습니다.

글꼴은 원본의 모든 글리프를 유지한 WOFF2 압축본입니다. 문자맵과 글리프 순서가 원본과 동일함을 검증했으며 원본 출처·SHA256도 기록했습니다. 글꼴 선택 화면을 열면 미리보기를 위해 여러 글꼴이 다운로드될 수 있습니다. 개구는 흔한 한글2,350자를 지원하고 나머지4종은 한글11,172자를 지원하여 나눔손글씨 펜을 대체 글꼴로 사용합니다. 글꼴 자체의 별도 유료 판매는 허용하지 않습니다.

## 데이터와 검증 한계

기기 간 동기화·로그인 계정은 없습니다. 브라우저 데이터 삭제, 비공개 모드 종료, 저장공간 정리 시 노트가 사라질 수 있습니다. 중요한 필기는 JSON으로 백업하세요.

자동 테스트는 획 보정/원본보존, undo/redo, 백업검증, 파일/DOM 연결, 서버 인증·요청검증·오류처리·모의 인식입니다. **모의 성공은 실제 AI 정확도 검증이 아닙니다.**

관리형 미리보기 시작이 timeout으로 끝났고 `sites-preview status`는 stopped였습니다. 로컬 미리보기는 우회하지 않았습니다. 이전 배포본은 공개 운영 URL의 Chrome에서 필기·키보드 편집·취소와 원본 보존을 확인했습니다. 새 자동 변환과 위치별 표시는 모의 테스트이며 운영 검증 상태는 별도 배포 보고를 따릅니다. 실제 iPad Pencil, 화면회전, Scribble, Safari의 다운로드/인쇄, 긴 필기 성능, 실제 Gemini 계정 인식은 후속 검증 대상입니다.

## 내 글씨체 추가 (기기 로컬 전용)
예쁜 필체 모드의 **내 글씨체 추가**에서 TTF, OTF, WOFF, WOFF2 파일을 선택하면 브라우저의 FontFace로 디코딩 확인 후 IndexedDB에 저장합니다. 글씨체 카드의 미리보기를 눌러 노트에 적용합니다. iPad 시스템 글꼴 설치가 아니며, 서버로 파일을 전송하지 않습니다. 해당 글꼴의 사용 권한은 사용자가 확인해야 합니다.

- 파일당 20MB, 최대 20개, 총 60MB. 확장자/파일 헤더 일치 검증, SHA-256 중복 검사, 브라우저 실제 디코딩 검증.
- 저장 공간 부족·브라우저 저장 제한·디코딩 실패 시 추가되지 않으며 오류를 알립니다.
- 저장된 폰트는 같은 브라우저에서 다시 불러옵니다. 비공개모드 종료·브라우저 데이터 삭제 시 사라질 수 있으니 원래 폰트 파일을 따로 보관하세요.
- JSON 노트 백업에는 폰트 **참조 ID만** 포함되고 폰트 파일은 포함되지 않습니다. 다른 기기에서는 동일한 파일을 다시 추가해야 합니다.
- 삭제하거나 로딩 실패한 폰트를 사용하는 노트는 원래 참조를 보존한 채 나눔손글씨 펜으로 대체하고 안내합니다. 동일 파일을 다시 추가하면 원래 폰트가 복원됩니다. 글씨체 삭제는 노트 내용을 삭제하지 않습니다.
- 문자 지원 범위는 폰트마다 다릅니다. 선택한 폰트에 없는 글자는 기본 폰트로 보일 수 있습니다.
- iPad/Safari 실제 폰트 불러오기·PNG/인쇄 렌더링은 실기기 검수가 필요합니다.

## 필기 입력 안정화와 인식 입력
- 종이 위는 기본 `touch-action: none`으로 고정됩니다. 손가락 쓰기 여부와 페이지 이동 여부는 별개입니다. 종이 밖에서 스크롤하거나 ‘페이지 이동 (필기 잠금)’을 켜세요. 이동 모드에서는 펜·손가락·마우스 모두 그리지 않습니다.
- 각 획의 시작 좌표계를 고정하고, 화면 크기/위치가 바뀌면 획을 안전하게 마칩니다. 취소된 획도 이미 받은 점은 보존합니다. 펜 사용 중 추가 손가락 입력은 무시하며 활성 획 동안 문서의 touchmove/wheel 기본 스크롤을 차단합니다. 기기 차원의 완전한 팜리젝션을 보장하지 않습니다.
- 빈 coalesced-events 배열을 반환하는 브라우저도 원래 이벤트를 기록하고, pointerup 마지막 점도 기록합니다.
- AI에는 원본 획의 전체 범위를 여백 포함 잘라 비율을 유지하며 최대 2배 확대(1,280×1,600 이내), 고대비 검정색으로 그린 이미지를 보냅니다. 저장된 원본 좌표·색상·보정 강도는 변경하지 않습니다. 한글을 우선 살피되 실제 영어·숫자를 한글로 강제하거나 임의 번역하지 않습니다.
- 이미 스크롤 때문에 손상된 획을 추측 복구하지 않습니다. 실제 iPad/Pencil 필기 및 유료 AI 인식 정확도는 별도 실기 검증이 필요합니다.

## 입력 경로 분리 (Scribble 혼동 방지)
두 모드 모두 기본 화면은 동일한 원본 SVG 필기 종이입니다. 예쁜 필체 모드는 글씨체만 고른다고 글자가 인식되지 않으며, 별도의 AI 변환 실행 또는 자동 변환 활성화와 전송 동의가 필요합니다. 변환 결과는 같은 SVG 종이의 해당 원본 필기 영역 안에 표시됩니다. 원본 보기는 같은 종이에서 표시하는 획만 바꾸며 별도 결과 화면으로 전환하지 않습니다.
‘키보드로 글 추가’는 별도 대화상자이며 추가를 눌러야 새 객체가 생깁니다. 기존 객체 수정은 객체를 선택한 뒤 글·크기 수정에서 합니다. 취소는 기존 글과 원본 획을 유지합니다. 편집칸에서 Pencil을 사용하면 iPad 자체 입력기가 작동할 가능성은 있지만, 앱은 그 언어나 설정을 강제하지 않으며 Nib AI 인식과 동일하다고 안내하지 않습니다. 이전 Scribble 입력 텍스트도 임의 삭제·교정하지 않습니다.

## 자동 변환과 직접 변환
- ‘지금 AI로 변환’은 최초 전송 동의·앱 이용 코드 확인 후 곧바로 결과를 적용합니다. 이전처럼 별도 결과 적용 버튼을 다시 누르지 않습니다. 오류는 화면에 표시하고 빈 결과를 성공으로 가장하지 않습니다.
- 자동 변환은 **별도 토글 및 최초 자동 전송 동의** 후에만 작동합니다. 필기를 약 1.8초 멈추면 새 획을 모으고, 실제 API 요청은 최소 10.5초 간격으로 직렬 처리합니다. 즉시 실시간 필체 변환은 아니며 대기·인식 상태가 표시됩니다. 반복 요청에 API 비용이 발생합니다.
- 앞서 변환한 획과 텍스트가 그대로면 새 획만 전송합니다. 편집·지우개 등으로 원본 앞부분이 달라졌다면 전체 원본을 다시 읽습니다. 같은 줄의 다음 묶음은 공백, 아래 줄은 줄바꿈으로 붙입니다. 음절 중간에 멈춰 끊어 쓰면 인식이 부정확할 수 있습니다. 문장 단위로 쓰고 결과를 확인하세요.
- 인식 중 새 필기, 노트 변경, 실행 취소 등으로 원본이 달라지면 오래된 응답은 적용하지 않습니다. 중복 내용은 페이지 메모리 캐시를 재사용합니다. 오류는 자동 재시도하지 않으며 연속 2회 실패하면 자동 변환이 꺼집니다. 이용 코드 오류는 즉시 중지합니다.
- 원본을 보는 동작, 키보드 편집, 실행 취소, 노트 전환, 앱 화면 이탈 시 자동 변환을 끕니다. 설정과 코드는 페이지 메모리에만 남으며 새로고침 뒤 자동 전송을 저절로 재개하지 않습니다. 이미 시작된 서버 호출의 비용은 취소만으로 취소된다고 보장할 수 없습니다.
- 자동 결과 표시 때도 SVG 필기 종이는 계속 입력을 받으며, 이미 변환한 획은 화면에서만 감추고 선택한 폰트 텍스트를 표시합니다. 원본 획은 저장·백업에 그대로 남습니다.

## 안전한 앱 업데이트 확인
앱 버전을 화면에 표시하고, 최신 버전이 있으면 새로고침 안내를 띄웁니다. ‘앱 새로고침’은 진행 중 작업이 없고 노트 저장이 성공한 경우에만 실행합니다. 사이트 데이터·IndexedDB·글씨체 저장소를 삭제하지 않습니다. 이미 열려 있는 구버전 탭은 최초 한 번 브라우저에서 새로고침해야 새 코드를 받습니다.

PNG에도 같은 위치의 변환 글씨와 아직 변환되지 않은 획을 함께 내보냅니다. 원본 보기에서는 원본 획을 내보냅니다.

## 같은 종이의 위치별 변환
- 변환 묶음마다 원본 획 ID와 외곽 영역을 함께 저장합니다. 해당 획만 화면에서 가리고 선택한 폰트로 겹쳐 표시하며 새 필기를 바로 이어 쓸 수 있습니다. 원본 좌표는 삭제하지 않습니다.
- 인식 API는 글자별 좌표를 반환하지 않습니다. 따라서 묶음의 원래 위치와 전체 영역을 유지하되 영역에 맞춰 글씨 크기/줄바꿈을 조정합니다. 원래 자간·단어별 정확한 위치를 재현한다고 보장하지 않습니다.
- 한 묶음은 최대 1,000자입니다. 최소 크기에서도 영역에 맞지 않으면 표시를 영역 안으로 제한하고 경고합니다. 전체 텍스트는 키보드 편집과 JSON 백업에 남습니다.
- 지우개로 묶음의 일부 원본 획을 지우면 해당 변환 표시를 풀고 남은 원본 획을 보여줍니다. 실행 취소로 묶음과 원본을 복원할 수 있습니다. 예전 백업도 읽되 위치 정보 없는 기존 텍스트의 원래 좌표를 추측 생성하지 않습니다.
- 로컬 95개 테스트와 구문 검사·빌드를 통과했습니다. 자동 API 응답은 모의 테스트이며 실제 유료 호출 및 iPad Pencil 실기 인식 정확도는 검증하지 않았습니다.

## 필기 중심 화면
상단 제목바, 실제 노트 탭, 한 줄 필기 도구 뒤에 바로 종이가 나옵니다. 펜·원형 부분 지우개·글 선택·화면 이동·되돌리기·굵기·색상·종이는 도구막대에서 조절합니다. 긴 도구막대와 노트 탭은 좁은 화면에서 각 줄만 가로 스크롤되며 본문 종이는 화면 폭 안에 유지됩니다.
노트 목록은 닫히는 패널이고, 글씨체·AI·보정 설정은 ‘글씨체 · AI’ 시트에서 엽니다. 시트를 열고 닫아도 원본과 위치별 변환 결과는 유지됩니다. 자동 인식의 동의 창에서 실행하면 설정 시트도 닫아 곧바로 종이에 이어 쓸 수 있습니다. Nib의 기존 기능을 재배치한 화면이며 다른 노트 앱의 전체 기능을 제공하는 것은 아닙니다.

## 표시용 원·직선 보정
설정 시트의 ‘원·직선 도형 보정’은 기본 꺼짐입니다. 켜면 페이지 좌표 기준 길이 48 이상 직선, 지름 64 이상인 신뢰도 높은 원만 반듯하게 표시합니다. SVG와 표시 PNG에 적용하며 저장·백업·AI 인식 입력은 원본 그대로입니다. 원본 보기, 토글 및 실행 취소로 돌아갈 수 있습니다.
타원·열린 호·나선·사각형·작은 자모 등은 원으로 강제하지 않습니다. 심하게 찌그러진 원은 그대로 남을 수 있습니다. 기하학만으로 크게 쓴 한글 ㅇ와 원, 아주 완만한 곡선과 흔들린 직선을 완전히 구별하지 못하므로 글씨가 바뀌면 토글을 끄세요. AI 호출 없이 기기에서 처리합니다.

## 원형 부분 지우개 · 공간 기반 보정
- 지우개는 선택한 원의 범위만 자르고, 빠르게 이동한 두 입력점 사이도 연속해서 지웁니다. 크기는 도구막대에서 바꿉니다. 한 번 드래그한 삭제는 한 번의 실행 취소로 복원됩니다. 지우기는 원본을 의도적으로 편집하는 동작이며, 보정의 원본 보기는 지운 부분을 복구하지 않습니다.
- 지우개 선택 중에는 삭제 위치가 맞도록 원본 획을 일시적으로 표시합니다. 폰트 변환 묶음의 일부 원본을 지우면 그 묶음은 풀고 남은 원본만 표시합니다. 지우개를 쓰면 자동 변환을 중지하며, 수정 후 다시 켤 수 있습니다.
- 필체 보정은 인접 3점 평균에서 실제 거리 기준의 국소 회귀로 바꿨습니다. 끝점·큰 모서리·원본은 보호하며 강도에 따라 잔떨림을 더 줄입니다. 합성 직선 샘플의 떨림 RMS는 원본 1.364, 이전 기본 보정 1.165, 새 기본 보정 0.433입니다. 이 수치는 해당 합성 테스트이며 사용자 필기 정확도나 예쁜 글씨 개선율이 아닙니다. 글자 골격·기울기·간격을 재설계하는 기능은 아닙니다.

## 이어 쓰기와 자동 변환
- 새 획이 이미 변환한 영역과 겹치면, 해당 기존 원본 획까지 함께 다시 인식하여 겹친 텍스트층을 추가하는 대신 교체합니다. 따라서 항상 새 획만 전송하는 것은 아닙니다.
- 여러 줄 원본은 줄마다 실제 시작 위치·폭에 나누어 배치합니다. OCR 개행이 맞지 않으면 원문 순서를 유지한 비례 배치이며, 글자별 정확한 좌표 인식이 아니라는 안내를 표시합니다.
- 펜이 종이에 닿아 있는 동안은 자동 전송/결과 적용을 기다리고, 펜을 뗀 뒤 약 1.8초 조용하면 예약합니다. 요청은 여전히 최소 10.5초 간격입니다. 대기·필기 중·인식 중·오류를 상태줄에 표시합니다. 기존 이미지의 자동 전송 중단 원인을 특정했다고 주장하지 않으며, 모의 연속 배치 테스트로 재예약을 검증했습니다.

## 인식 제한시간과 재시도
- 화면에 있었던 ‘인식 시간이 초과되었습니다’ 문구는 기존 서버의 30초 제한 분기와 일치합니다. 공급자 응답이 왜 늦었는지는 실호출/로그 없이 확정하지 않았습니다.
- 현재 요청 한 번의 제한은 **Gemini 응답·본문 50초 → Vercel 함수 60초 → 브라우저 70초**입니다. 무한 대기나 자동 재시도를 하지 않습니다. 12초 이상 기다리면 진행 중 안내를 표시합니다. 브라우저는 `AbortSignal.any` 지원 여부와 무관하게 외부 취소와 자체 제한시간을 함께 적용합니다.
- 시간 초과/불확실한 서버·연결 실패는 자동 모드를 즉시 끄며, 새 필기를 써도 몰래 재전송하지 않습니다. ‘인식 재시도’를 누른 뒤 이전 호출 및 추가 비용 가능성을 확인해야 재전송합니다. 서버/호스팅/브라우저 제한과 네트워크 실패 코드를 구분합니다.
- 정상 완료 응답이 왔지만 필기가 바뀌어 적용하지 못한 경우에도 ‘최근 인식 결과’로 확인할 수 있습니다. 페이지 메모리에 최대 12개 노트의 최근 결과만 보관하고 새로고침/종료 시 사라집니다. 이미 취소·시간 초과되어 수신하지 못한 공급자 결과를 복구하는 영구 작업 저장소는 아닙니다.
- `thinkingConfig.thinkingLevel: minimal`을 명시했습니다. [Gemini 3.1 Flash-Lite 공식 표](https://ai.google.dev/gemini-api/docs/generate-content/gemini-3#thinking_level)에서 이미 기본값이므로 이것이 시간 초과 원인이었다고 주장하지 않습니다. [generateContent 필드](https://ai.google.dev/api/generate-content#ThinkingConfig), [Vercel 실행시간 설정](https://vercel.com/docs/functions/configuring-functions/duration)을 참고했습니다. 4,096 출력 토큰 한도는 유지했습니다. 이후 불필요한 이미지 확대를 줄이는 변경은 아래를 참고하세요.
- 31초 지연 성공, 50초 fetch/본문 중단, 70초 브라우저 중단, 단일 호출, busy 해제, 늦은 응답 보관은 mock 테스트입니다. 실제 Gemini 지연·성공률을 실측하지 않았으며 실기 재확인이 필요합니다.


### 글 선택·이동 및 반복 인식 경량화
- ‘올가미’로 자유롭게 둘러 필기를 고르고(사각 선택 옵션도 제공), 선택 영역 안을 끌어 이동합니다. 기존 ‘이동’은 ‘화면 이동’으로 구분했습니다.
- 변환 글을 일부만 선택해도 그 글의 원본 묶음 전체가 함께 선택됩니다. 원본 좌표와 표시 영역을 같은 거리만큼 옮기고 종이 경계를 넘지 않게 제한합니다. 한 번 드래그는 한 번에 실행 취소할 수 있습니다. 키보드만 입력하여 원본 획이 없는 이전 텍스트는 선택 이동 대상이 아닙니다.
- 이동 중에는 자동 인식을 중지하고, 변경 전 원본을 대상으로 한 늦은 응답을 적용하지 않습니다. 이동 후 자동 변환을 다시 켤 수 있습니다.
- 수동 재시도도 기존 글 전체가 아닌 미변환 획과 그 근처의 필요한 기존 원본 묶음만 전송합니다. 여러 줄을 감싼 사각형의 빈 공간 때문에 기존 묶음 전체가 재전송되는 경우를 줄였습니다. 작은 후속 자모가 가까이 추가되면 기존 묶음을 함께 인식할 수 있습니다.
- PNG는 원본보다 작게 줄이지 않고 최대 확대율을 3배에서 2배로, 최대 크기를 1,280×1,600으로 제한합니다. 모델 해상도 옵션과 모델은 바꾸지 않았습니다. 픽셀 수/전송량 감소가 실측 인식 지연 또는 정확도 향상을 보장하지는 않습니다.
- 서버는 정상 인증·유효 인식 요청에 대해 한 번의 메타데이터 로그를 남깁니다: 무작위 요청 ID, 전체/헤더까지 소요시간, HTTP 상태, 제한된 오류·종료 사유, fetch/body/validate 단계. 원본 이미지·필기·인식 결과·키·IP·사용자 제공 헤더·원본 예외는 기록하지 않습니다. 오류에 표시되는 문의 ID로 호스팅 로그와 대조할 수 있습니다.
- 첫 응답 전 지연인지 본문 수신 지연인지 앞으로 구별할 수 있지만, 실제 유료 호출은 수행하지 않았으므로 사용자 기기의 50초 초과 원인은 아직 확정하지 않았습니다. 스트리밍도 첫 응답 지연을 없애거나 불완전한 JSON을 안전한 확정 결과로 바꾸지는 않으므로 이번 변경에는 넣지 않았습니다.

- 선택 도구는 기본 자유형 올가미입니다. 그리는 도중에는 올가미 선, 선택 후에는 실제 선택 범위의 사각 윤곽을 표시합니다. 기존 변환 묶음 일부만 둘러싸도 묶음 전체가 선택되며 안내에 이 단위를 명시합니다.
- 선택 도구 아래의 ‘선택 글 AI 변환’은 선택된 원본 묶음만 전송합니다. ‘선택 폰트 적용’은 이미 읽은 선택 그룹의 폰트·크기만 바꾸며 AI를 호출하지 않습니다. 아직 읽지 않은 원본은 폰트만으로 변환할 수 없다는 안내를 표시합니다.
- 그룹마다 선택한 폰트/크기를 저장하고 JSON 백업에서도 보존합니다. 설정창의 기본 폰트를 바꿀 때 기존 그룹의 스타일을 고정하므로, 선택하지 않은 기존 글은 바뀌지 않습니다. 원본이 없는 이전 직접입력 글은 기존 기본 폰트 방식입니다.
- 선택 해제·다시 선택·선택 폰트 변경·원본 이동·노트 변경 도중 도착한 선택 인식 응답은 자동 덮어쓰지 않습니다. 선택 변환은 자동 변환과 병렬 실행하지 않습니다.


### 노트북과 여러 페이지
- 기존 저장된 단일 노트는 각각 같은 제목의 노트북 1페이지로 읽습니다. 원본 획·선택 폰트·변환 묶음·기존 페이지 ID를 바꾸거나 기존 저장소를 삭제하지 않습니다.
- 새 노트를 만든 뒤 상단 제목에서 이름을 정합니다. ‘＋ 페이지’는 현재 노트에 빈 다음 페이지를 추가합니다. 이전/다음 화살표와 ‘현재 / 전체’ 페이지 목록으로 이동합니다. 노트 탭을 오가면 세션 중 마지막 페이지로, 새로고침하면 마지막으로 열었던 페이지로 돌아갑니다.
- 각 페이지는 고유 ID와 별도 필기/변환/폰트/종이 설정을 가집니다. 추가 페이지는 현재 페이지의 도구 설정만 복사하고 내용은 복사하지 않습니다. 실행 취소는 페이지별로 분리되며 최근 방문 페이지 최대 8개와 현재 페이지의 메모리 이력을 유지합니다. 새로고침 후 실행 취소 이력은 복구되지 않습니다.
- 페이지 전환은 저장 성공 후에만 진행하고 중복 클릭을 막습니다. 자동 변환은 전환 시 꺼집니다. 이전 페이지 또는 이전 선택을 대상으로 한 늦은 응답은 새 페이지에 적용하지 않습니다.
- 노트 제목 변경과 전체 노트 삭제는 해당 페이지들을 하나의 IndexedDB 트랜잭션으로 처리합니다. 다른 창의 수정 충돌이나 저장 실패 시 일괄 작업을 중단합니다. 노트 삭제는 모든 페이지를 삭제하므로 페이지 수를 확인하는 경고가 표시됩니다.
- 최대 100개 노트북, 합계 1,000페이지입니다. 페이지별 원본 크기 제한은 기존과 같습니다. 종이 위에는 한 페이지만 표시하므로 긴 노트도 다른 페이지 전체를 렌더링하지 않습니다.
- ‘현재 노트 전체 페이지 백업’은 모든 페이지의 JSON 백업, 사이드바 ‘백업 저장’은 모든 노트의 JSON 백업입니다. PNG와 인쇄/PDF는 **현재 페이지**만 지원하며 UI에 구분했습니다.
- 기존 version 1 백업도 읽습니다. 새 백업은 페이지 묶음 ID/순서를 추가로 보존합니다. 24MB 초과 백업은 여러 파일로 나뉩니다. 같은 백업의 분할 파일은 **새로고침하지 않고 같은 세션에서** 모두 불러오면 하나의 복사본 노트로 합쳐지며 중복 파일은 건너뜁니다. 새로고침 후 나머지를 불러오면 별도 복사본으로 들어가므로 모든 분할 파일을 같은 세션에서 불러오세요. 커스텀 폰트 바이너리는 이전과 같이 별도 보관해야 합니다.

### 올가미 범위·인식 대기 수정 (v.8, 로컬 검증)
- 변환 묶음 일부를 스쳤다는 이유로 멀리 있는 다른 줄까지 자동 선택하지 않습니다. 전체가 둘러싸인 변환 묶음만 선택하며 부분적으로 걸친 묶음은 제외하고 안내합니다. 원본 획은 실제 올가미 교차 기준입니다. 낱글자의 정확한 OCR 좌표는 없으므로 변환 묶음 내부 임의 문자 선택은 지원하지 않습니다.
- 인식 대기 중 경과 초와 응답 수신 상태를 표시하고 ‘인식 대기 취소’를 제공합니다. 취소는 브라우저 대기를 끝내지만 이미 서버에 전송한 작업·비용까지 취소하지는 못합니다. 재전송은 비용 경고를 확인해야 하며 자동 재시도하지 않습니다. 전송 전 취소된 요청은 fetch 자체를 실행하지 않습니다.
- Gemini 3 공식 권고에 맞춰 temperature:0 강제 설정을 제거했습니다. minimal thinking·출력 상한 4096·이미지 해상도·서버 50초/호스팅 60초/브라우저 70초 제한은 그대로입니다. 출력 상한은 매번 생성되는 토큰 수가 아닙니다. 실제 유료 호출 없이 모의 응답으로 검증했으므로 실제 지연 개선·인식 품질은 미측정입니다.
- 근거: https://ai.google.dev/gemini-api/docs/generate-content/gemini-3#temperature , https://ai.google.dev/gemini-api/docs/media-resolution . 한글 세부 획 손실 가능성이 있어 low 해상도로 낮추지 않았습니다.
- 명시적 줄바꿈 수와 원본 행 수가 일치하고 기존 표시 위치를 그대로 유지할 수 있는 다중행 결과는 독립적인 줄 묶음으로 나눕니다. 이제 그 줄 전체를 둘러싸서 이동·폰트 변경·재인식할 수 있고 위쪽 줄은 건드리지 않습니다. 기존 텍스트 조각·줄바꿈과 원본 획 ID를 보존합니다. 줄 대응이 모호한 결과는 임의로 쪼개지 않고 원래 묶음을 유지합니다.

### 앱 자체 대기시간 단축·지연 진단
- 자동 변환의 필기 멈춤 대기는 1.8초에서 1.2초로 줄였습니다. 기존 요청 사이 10.5초 강제 간격 대신 수동·자동이 공유하는 최근 60초 최대 6회 예산을 사용합니다. 예산이 남으면 이전 요청 완료 뒤 불필요한 간격 없이 다음 묶음을 처리합니다. 7번째는 남은 초를 표시하며 기다립니다. 병렬 인식과 중복 요청은 하지 않습니다.
- 취소·실패한 요청도 이미 시작했다면 예산에 남고, 노트/페이지 전환으로 초기화하지 않습니다. 브라우저 재시작·여러 탭/사용자 사이에서는 로컬 예산이 공유되지 않으므로 서버 제한이 최종 기준입니다. 서버 429가 오면 자동 변환을 끄고 유효한 Retry-After만 안내하며 자동 재시도하지 않습니다.
- 서버의 비밀정보 없는 진단에 안전한 정수 토큰 수, 검증된 모델 버전, 응답 헤더/본문/전체 소요시간을 추가했습니다. Server-Timing에는 숫자 시간만 표시합니다. 비스트리밍 headersMs는 모델 생성 대기를 포함할 수 있어 순수 네트워크 지연이나 첫 토큰 시간으로 해석하면 안 됩니다. 실제 콜드스타트·서비스 지연은 측정 전입니다.
- 스트리밍은 아직 사용하지 않습니다. 불완전한 JSON이나 일부 인식 문구를 종이에 적용하지 않고 검증된 최종 결과만 반영합니다. 이 수정은 앱이 강제하던 대기만 줄이며 Gemini 자체 응답속도를 보장하지 않습니다.

### 변환 글 손가락 즉시 이동 (v.9, 로컬 검증)
- 예쁜 필체 모드에서 화면에 표시된 변환 글에 손가락을 누르고 바로 끌면 이동합니다. 길게 누르거나 올가미를 먼저 선택할 필요가 없습니다. 실제 SVG 글자 경계와 종이의 줄 표시영역을 교차해 잡으므로 넓은 문단 여백을 눌러 이동하지 않습니다.
- 잡힌 줄/묶음의 실제 글자영역에 작은 점선 테두리를 표시하고 원본 획·변환 위치를 함께 이동합니다. 명확하게 나뉜 줄은 독립 이동하며, 나누기 모호한 기존 결과는 묶음 전체가 움직입니다. 낱글자 단위 이동은 지원하지 않습니다.
- 펜 입력은 글을 잡지 않고 필기합니다. 다른 포인터가 활동 중이거나 추가 손가락·큰 접촉면(40 CSSpx 초과)이 감지되면 이동하지 않습니다. 화면 이동 모드, 원본 보기, 지우개 모드에서는 직접 잡기를 끕니다. 접촉 크기를 제공하지 않는 기기는 손바닥 완벽 구별을 보장할 수 없습니다.
- 한 드래그는 실행 취소 한 번으로 복원합니다. 페이지 경계를 벗어나지 않도록 제한하고, 포인터 취소 시 이미 이동한 위치는 저장하되 활성 테두리·캡처를 정리합니다. 이동 중 자동 변환은 꺼지며 늦은 AI 결과는 새 위치를 덮어쓰지 않습니다. 실제 iPad/Pencil 동작은 별도 확인이 필요합니다.

- 화면·페이지 미리보기·PNG·인쇄에는 같은 코드 기반 배경 도형을 사용합니다. 인쇄 색상은 브라우저/프린터 설정에 따라 달라질 수 있습니다. OCR 입력은 기존 흑백 원본 필기만 사용하므로 장식을 AI에 전송하지 않습니다.
- 속지는 JSON 백업/복원에 포함됩니다. 속지 적용은 메타데이터 변경으로 필기 Undo/Redo와 분리합니다.
- 참고: [MIDORI 종이 소개](https://www.midori-japan.co.jp/english/products/paper/), [MIDORI 편지지 컬렉션](https://www.midori-japan.co.jp/english/products/letterpad-envelope/), [Papier Timeless](https://www.papier.com/timeless-227). 미색과 절제된 편지지 구성에서 방향만 참고했으며 원본 이미지·꽃무늬·상표를 복제하지 않고 자체 SVG 기하 도형으로 제작했습니다.

### 펜 6종 · 필압과 질감
- 도구막대의 펜 이름을 눌러 **연필·만년필·볼펜·형광펜·사인펜·색연필**을 선택합니다. 굵기·색상·실제 필압은 각 획에 저장하며, 선택 변경은 새 획에만 적용합니다.
- Apple Pencil 등 압력 지원 Pointer Events 펜은 압력값(0~1)을 사용합니다. 마우스·터치는 일정한 0.5 압력입니다. 선택창의 압력 변화는 시연용 예시이며 마우스 필기를 실제 필압처럼 꾸미지 않습니다.
- 만년필은 굵기 변화를 크게, 볼펜은 작게, 사인펜은 중간 정도 반영합니다. 연필·색연필은 결정론적 입자, 형광펜은 넓은 반투명 획입니다. 실제 종이 마찰·촉감은 재현하지 않습니다.
- SVG/PNG는 같은 획 기하 데이터를 사용합니다. 형광펜 한 획 안의 겹침은 한 번만 칠하고 서로 다른 획은 누적됩니다. 최대 2,048개 표시 샘플·1,600개 입자로 렌더링 비용을 제한하며 원본 데이터는 자르지 않습니다. 많은 장문의 필기에서 실제 iPad 성능은 미검증입니다.
- 예전 획은 원래 일정 굵기의 선으로 유지하며, 백업·지우개 조각에도 스타일/압력을 보존합니다. 보정은 좌표를 다듬되 압력 데이터를 보존합니다. OCR에는 스타일·종이 장식 없이 원본 좌표의 검정 선만 전송합니다.

### 페이지 삭제 · v14
- 상단 페이지 이동 막대의 **페이지 삭제**는 현재 페이지만 삭제합니다. 확인창에 노트 이름, 현재 페이지 번호와 전체 페이지 수를 표시하며 다른 페이지는 유지됩니다. 취소하면 삭제하지 않습니다.
- 삭제는 되돌릴 수 없으므로 확인창 안내대로 먼저 **내보내기 → 노트 백업(JSON)**을 권장합니다. 노트의 마지막 한 페이지는 삭제할 수 없습니다. 노트 전체를 지우려면 서재의 **노트 삭제**를 사용합니다.
- 삭제 대상과 노트 소속·남은 페이지 수를 같은 IndexedDB 쓰기 트랜잭션에서 검사합니다. 다른 창에서 마지막 두 페이지를 동시에 삭제해도 마지막 한 페이지를 보호합니다. 버전 충돌 시 삭제하지 않습니다.
- 삭제한 페이지의 Undo·임시 인식 결과를 제거하고 다음 페이지(없으면 이전 페이지)를 엽니다. 이미 전송한 AI의 대기 취소가 요금 취소를 뜻하지는 않습니다. 늦은 응답은 삭제된 페이지를 되살리지 않습니다.

### 펜 전환·올가미 수정 함께 복구
- 펜 종류 적용은 지우개/선택/화면 이동을 해제하고 실제 펜 도구를 활성화합니다. 취소는 기존 도구를 유지합니다.
- 원본 획이 사라진 독립 텍스트 객체도 선택·이동·폰트 변경할 수 있습니다. 여러 줄 객체는 보이는 글 전체를 둘러싸면 한 객체로 선택됩니다. 글자 단위 분할은 하지 않습니다. 손가락 올가미는 손가락 필기 옵션과 독립적으로 동작합니다.
- 이번 환경에서는 브라우저 제어 도구가 없어 실제 브라우저 및 iPad 검증은 하지 못했습니다. 실제 앱 이벤트 핸들러를 실행하는 테스트와 저장소 트랜잭션 테스트로 확인합니다. 이전 버전의 브라우저 검증을 이번 버전의 검증으로 간주하지 않습니다.

### 지우개 초기 반응 개선
- 닿을 수 없는 먼 획은 정확한 교차 계산 전에 제외합니다. 닿는 획은 기존 원형·이동 경로 전체(swept capsule) 부분 삭제를 그대로 사용합니다.
- 변하지 않은 획의 SVG 노드를 재사용하고, 한 포인터 이벤트에 포함된 여러 샘플은 모두 삭제 계산하되 화면 갱신은 한 번으로 모읍니다. 새 필기·보정 변경·지우개 조각은 새 노드를 사용합니다. 원형 커서는 계산 전에 위치를 갱신합니다.
- Node 합성 대용량 비교는 개선 여부의 참고일 뿐 실제 iPad 지연·필압 감도 검증을 대체하지 않습니다. 첫 Undo 스냅샷 복사와 대량으로 실제 교차하는 획의 비용은 여전히 남아 있습니다.

### 하나로 정리한 선택 도구 · v15
- 상단에는 **올가미 아이콘 하나**만 표시합니다. 별도 사각 선택 드롭다운은 제거했습니다. 접근성 이름은 ‘올가미 선택’입니다.
- 원하는 글을 자유형으로 둘러 선택한 뒤, 표시되는 사각 테두리 안을 끌어 이동합니다. 사각 테두리는 선택 결과 표시이며 별도 선택 모드가 아닙니다. 이전 사각 선택 UI 상태는 사용하지 않습니다.
- 원본 획과 독립 텍스트 객체의 이동·선택 폰트·Undo 및 펜/지우개 전환은 유지합니다. 실제 iPad 조작은 아직 미검증입니다.

### 선택 이동 취소 · v16
- 올가미로 선택한 글의 이동은 드래그 중 화면 미리보기만 하고, 정상 `pointerup` 때 한 번의 Undo와 저장으로 확정합니다. 미리보기 좌표는 자동 저장 목록에 넣지 않습니다.
- 진행 중 선택 이동에서 선택 해제·도구 변경·페이지 전환·포인터 취소/캡처 상실·화면 좌표 변화가 생기면 이동 전 필기와 객체 위치로 돌아갑니다. 펜 필기와 지우개의 이미 처리된 획을 보존하는 기존 취소 정책은 바꾸지 않습니다.
- 올가미 선택 이동에는 화면 기준 6px 흔들림 방지 범위를 적용합니다. 기존 변환 글의 직접 손가락 이동은 길게 누르기 없이 즉시 미리보기되며 정상적으로 손을 떼면 저장됩니다.
- 정상적으로 끝낸 이동 뒤 ‘선택 해제’는 선택 테두리만 없앱니다. 이미 확정한 잘못된 이동은 Undo로 되돌려야 하며, 이전에 저장된 위치를 추측해서 복원하지 않습니다. 실제 사용자 사진의 변경 전 원본은 없어 정확한 이전 좌표는 확인하지 못했습니다.

### 변환 글 객체 삭제 · v16
- 변환 글을 올가미로 선택하거나 **손가락으로 가볍게 누른 뒤**, 아래 **선택 삭제**를 누릅니다. 실제 드래그는 계속 즉시 이동하며 길게 누를 필요가 없습니다.
- 선택한 객체와 연결된 원본 획을 함께 삭제하므로 원본 보기·자동 변환·다시 열기에서 삭제한 글이 되살아나지 않습니다. 선택하지 않은 독립 객체와 다른 페이지는 유지합니다. 원본 획만 선택하면 그 획을 삭제합니다.
- 삭제는 한 번의 Undo로 객체·원본·위치를 함께 복원할 수 있습니다. 원형 지우개는 기존처럼 원본 획의 부분 삭제 도구이며 변환 글 전체를 몰래 지우지 않습니다.
- 진행 중인 이동 미리보기에서 삭제를 실행하면 먼저 이동 전 위치로 되돌린 뒤 삭제합니다. AI 응답 대기는 취소하고 삭제 전 응답의 재적용을 막습니다. 이미 전송된 요청의 요금 취소는 보장하지 않습니다.

### 같은 페이지 폰트 변환·수정·원본 복원 · v17
- 종이 위 **Aa 폰트로 변환**에서 전체 필기 또는 선택한 필기를 기존 AI 동의·연결 절차로 변환합니다. 결과는 현재 페이지에 나타나며 필기 보정과 변환 글씨체 설정도 같은 페이지에 적용됩니다.
- 변환 글 하나를 선택한 뒤 **글·크기 수정**을 누르면 페이지 안에서 내용과 글 상자의 너비·높이를 바꿀 수 있습니다. 다른 글과 원본 획은 유지합니다. 취소는 변경하지 않고 적용은 한 번의 Undo로 되돌립니다. 변환 글은 키보드 Tab 및 Enter/Space로도 선택할 수 있습니다.
- **손글씨로 되돌리기**는 선택한 변환 글만 제거해 보관된 원본 획을 다시 보여줍니다. 저장 후 다시 열어도 원본이 유지되고, 복원 직후 Undo로 변환 글을 되살릴 수 있습니다. 연결된 원본이 지워졌거나 다른 글과 공유되는 경우에는 안내 후 현재 내용을 유지합니다.
- 구문 검사·567개 자동 테스트·빌드 통과. 브라우저에서 글 수정, 상자 크기 조절, 원본 복원, Undo 및 새로고침 후 저장 유지를 확인했습니다. 실제 AI 인식 호출과 iPad/Pencil 입력은 이번 변경에서 검증하지 않았습니다.

## 그림 도구 스크롤 충돌 수정 (2026.10.29.20)
- 원인: 화면 이동 모드의 실제 CSS 클래스는 `page-pan`인데 그림 메뉴는 `panning`을 제거해 `touch-action:pan-y`가 남았습니다. 체크박스만 꺼져 보인 채 브라우저가 손가락 스크롤을 시작하고 pointercancel/좌표 변경으로 그림이 취소될 수 있었습니다.
- 그림 메뉴를 여는 시점에 `page-pan`을 제거하고 손가락 입력 설정의 disabled도 해제합니다. 그림 모드의 명시적인 `touch-action:none`은 첫 접촉 전 적용하며, 기존 펜·지우개·올가미·화면 이동 선택 시 해제합니다. 그림 Pointer Event는 명시적으로 non-passive capture listener를 사용합니다.
- 실제 입력 취소는 원본을 바꾸지 않고 안내한 뒤 다음 제스처를 허용합니다. 페이지 밖/팔레트의 정상 스크롤과 명시적인 화면 이동 기능은 유지합니다.
- [MDN touch-action 설명](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action): 브라우저는 제스처 시작 시 터치 처리 방식을 결정하므로 pointerdown 뒤 설정 변경만으로 이미 시작한 스크롤을 막을 수 없습니다.
- 앱 콜백 재현 테스트에서 수정 전 클래스 잔존 실패를 확인하고 수정 후 통과했습니다. 실제 iPad 브라우저에서 전체 증상을 재현한 것은 아니므로 모든 멈춤 원인이 해결됐다고 단정하지 않습니다.

## 도형 입력 안정화 · 선 끝점 편집 (2026.10.29.21)
- Pencil 도형 제스처 중 다른 손바닥/터치가 닿았다는 이유만으로 취소하지 않습니다. 손가락으로 그리는 동안 두 번째 손가락이 들어오면 기존 안전 취소를 유지합니다. 종이 밖 손바닥 스크롤 방지도 도형 제스처 동안 적용하며, 제스처가 끝나면 정상 스크롤을 허용합니다.
- 화면의 top/left 변화는 현재 종이 위치로 좌표를 다시 계산해 이어갑니다. 페이지/내용 변경이나 실제 종이 크기·배율 변경은 여전히 미리보기를 취소합니다. 실기 Safari에서 모든 끊김 원인을 확인했다는 의미는 아닙니다.
- 새 직선·화살표는 시작점과 끝점의 실제 좌표를 따로 저장합니다. 수평·수직·모든 대각 방향과 반대 방향 드래그가 유지되며 화살촉은 끝점에 위치합니다.
- **그림 → 선택·이동**에서 선을 선택하면 양 끝 손잡이가 나타납니다. 끝을 끌어 각도/길이/방향을 자유롭게 바꿀 수 있고, 가운데 선을 끌면 전체가 이동합니다. 선에서 멀리 떨어진 사각 영역은 선택하지 않습니다.
- 기존 저장 선은 이전 화면 모양을 유지하며 새 좌표 형식으로 복원합니다. 옛 최소 1픽셀 상자에서 잃었던 정확한 수평/수직 원래 좌표를 추측 복구하지는 않습니다. 끝점 편집으로 조정할 수 있습니다.
- 원본 필기/글씨 객체, 페이지별 실행 취소, 백업/미리보기/PNG의 기존 동작은 유지됩니다. 유료 AI 호출 없이 작동합니다. 네이티브 브라우저 입력은 AT-SPI 연결 오류로 실행하지 못했으며 실제 iPad는 미검증입니다.

## 손가락 도형 이동 · 페이지 쓸어 넘기기 (2026.10.29.22)
- **기본 펜 모드**에서 손가락으로 도형·표·선 위를 누른 채 바로 끌면 전체 객체가 이동합니다. 길게 누르거나 올가미를 먼저 고를 필요가 없습니다. 짧게 탭하면 선택된 객체의 그림 편집 팔레트가 열립니다. 드래그만 한 경우에는 펜 모드를 유지해 곧바로 빈 종이에서 페이지를 넘길 수 있습니다.
- 빈 종이에서 **왼쪽으로 쓸기 → 다음 페이지**, **오른쪽으로 쓸기 → 이전 페이지**. 최소 80화면픽셀, 가로 움직임이 세로의 2배 이상인 짧은 한 번의 제스처만 받습니다. 첫/마지막 페이지에서는 안내만 표시하고 새 페이지를 만들지 않습니다.
- 객체·글·원본 획 위에서 시작한 터치는 페이지 넘김으로 처리하지 않습니다. 도형/글 이동이 우선입니다. **손가락으로 쓰기**, 지우개, 올가미, 그림 팔레트 사용 중에는 빈 종이 넘김을 끕니다. 그림 팔레트를 닫고 기본 펜 모드로 돌아오면 다시 사용할 수 있습니다.
- Pencil은 기존 필기/도형 입력용입니다. 손바닥·다중 터치·짧은 탭·세로 움직임·화면 크기 변경·페이지 변경은 넘김을 취소합니다. 정상 페이지 전환은 기존 자동저장 확인 경로를 사용하고 저장이 실패하면 현재 페이지에 머뭅니다.
- 직접 객체 이동은 한 번 실행 취소할 수 있고, 취소된 미리보기는 저장하지 않습니다. 실제 iPad와 브라우저 제스처는 별도 실기 검증이 필요합니다. AI 호출은 없습니다.

## 화면 이동 모드의 페이지 넘김 수정 (2026.10.29.23)
- **화면 이동을 켠 상태에서도** 빈 종이를 좌우로 쓸면 이전/다음 페이지로 넘어갑니다. 위아래 쓸기는 브라우저의 세로 스크롤에 맡깁니다. 이전에 선택했던 지우개/올가미나 손가락 필기 설정은 화면 이동 모드에서 페이지 넘김을 차단하지 않습니다.
- 첫 터치부터 모든 스크롤을 막지 않고 가로 의도가 확인된 뒤에만 기본 스크롤을 차단합니다. Pointer/Touch 이벤트가 다른 순서로 와도 탐색 실행은 pointerup 한 곳에서만 하여 중복 페이지 이동을 방지합니다.
- 화면 이동을 끈 필기 모드의 기존 안전 제약, 객체/필기 위 터치 제외, 저장 실패 시 전환 중단, 첫/마지막 페이지 보호는 유지합니다.
- 확인된 원인은 화면 이동 체크박스가 page-pan CSS를 켜면서 동시에 페이지 넘김 조건을 false로 만들던 모순입니다. 사용자 기기의 당시 체크 상태나 Safari의 모든 동작까지 확인한 것은 아닙니다. 실제 iPad 제스처는 미검증입니다.
- 근거: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action 및 https://www.w3.org/TR/pointerevents/ — 브라우저 기본 제스처는 시작 시 touch-action으로 결정되고 브라우저가 처리하면 pointercancel이 발생할 수 있습니다.

## 터치 시작부터 페이지 제스처 소유 (2026.10.29.24)
- 터치 이벤트 지원 브라우저에서는 빈 종이의 `touchstart`를 즉시 취소해 브라우저 스크롤과 경쟁하지 않고, `touchend` 한 곳에서만 페이지를 넘깁니다. 중간 `pointercancel`이 와도 별도로 소유한 터치 제스처를 버리지 않습니다. 실제 `touchcancel`, 다중 터치, 펜 입력, 페이지/크기 변경은 안전 취소합니다.
- 12px 이상 움직여 우세 방향이 1.25배 이상이면 가로/세로 방향을 잠급니다. 가로로 잠긴 제스처는 나중에 약간 대각선으로 움직여도 화면 스크롤로 바뀌지 않습니다. 3초 이내 가로 60px 이상 쓸 때 한 페이지 이동합니다. 45도 부근처럼 의도가 모호한 움직임은 넘기지 않습니다.
- 빈 종이에서 세로로 시작한 제스처는 앱이 문서의 세로 스크롤 위치를 움직입니다. 브라우저 기본 관성 스크롤과 같은 감촉을 보장하지 않으며, 종이 밖의 기존 스크롤은 유지합니다. 글/도형 위 터치는 이 경로가 소유하지 않아 기존 편집/이동을 보존합니다.
- Pointer-only 브라우저에는 이전 안전 경로를 남깁니다. 실제 iPad Safari 제스처는 미검증입니다. 운영 v23의 네이티브 Chromium 화면·페이지 추가·이전 버튼은 직접 확인했지만 마우스 버튼 검증을 손가락 성공 증거로 사용하지 않습니다.
- 표준 근거: https://www.w3.org/TR/touch-events/ (`touchstart` 취소의 기본 스크롤 방지), https://www.w3.org/TR/pointerevents/ (PointerEvent 취소와 viewport 기본 동작 구분). 이번 변경이 사용자 기기의 원인을 확정하거나 실기 성공을 보장한다는 의미는 아닙니다.

## 두 손가락으로만 화면 이동 (2026.10.30.25)
- 종이 위 **한 손가락 좌우 쓸기 = 페이지 넘김**, **두 손가락 이동 = 화면 세로 이동**으로 분리했습니다. 한 손가락 세로/대각 이동은 더 이상 화면을 스크롤하지 않습니다. 글/도형 위 한 손가락은 기존 객체 이동을 유지합니다.
- 화면 이동 모드도 `touch-action:none`으로 시작부터 브라우저의 한 손가락 스크롤을 막습니다. 종이 밖 도구/메뉴/입력창의 기존 스크롤은 변경하지 않습니다.
- 두 손가락 모두 종이 위에서 시작해야 하며 중심의 이동량으로 문서를 스크롤합니다. 두 번째 손가락이 닿는 순간을 기준으로 잡아 첫 이동 점프를 방지합니다. 1→2→1 전환 후 남은 손가락을 페이지 넘김으로 승격하지 않고 모두 뗄 때까지 기다립니다.
- 세 손가락, 핀치 거리 변화, 페이지/종이 크기 변경, touchcancel은 안전 취소합니다. 핀치 확대 기능을 새로 제공하지 않습니다. Pencil 입력 중 손바닥/터치로 화면이 움직이지 않도록 펜 활성 상태를 확인합니다.
- 두 손가락 이동을 시작할 때 아직 저장하지 않은 손가락 펜 미리보기는 버리고, 객체 이동 미리보기는 원위치로 복원합니다. 이미 적용한 지우개 결과나 기존 필기는 그대로 둡니다.
- 실제 iPad 감도와 브라우저의 관성 스크롤 감촉은 미검증입니다. 두 손가락 스크롤은 직접 위치를 갱신하며 새 AI 호출이 없습니다.

## 두 손가락 페이지 이동 + 브라우저 확대·축소 (2026.10.30.26)
- 최신 조작은 **Pencil/한 손가락 = 기존 필기·객체 조작**, **두 손가락을 나란히 좌우로 쓸고 모두 떼기 = 이전/다음 페이지**, **두 손가락 벌리기·모으기 = 브라우저 핀치 확대·축소**입니다. v24의 한 손가락 페이지 넘김과 v25의 수동 두 손가락 스크롤은 제거했습니다.
- 기본·화면 이동·그림 모드의 종이는 처음부터 `touch-action:pinch-zoom`입니다. 페이지 제스처는 passive TouchEvent 관찰만 하며 `preventDefault()`를 호출하지 않습니다. 손가락으로 글/도형을 옮기는 중에도 전역 touchmove를 취소하지 않습니다. 실제 Pencil 접촉 중에는 손바닥 방어를 유지합니다.
- 두 손가락 사이 간격/각도 변화, 반대 방향 이동, 실제 viewport 배율 변화, touchcancel이 있으면 페이지 전환을 포기합니다. 가로 평행 이동은 두 손가락을 모두 뗀 뒤만 반영합니다. 하나를 뗀 동안 새 필기나 페이지 전환으로 승격하지 않습니다. 첫/마지막 페이지에서 새 페이지를 자동 생성하지 않습니다.
- 확대는 자체 종이 transform이 아니라 브라우저 기능입니다. 핀치를 나중에 되돌려 주는 방식이 아니라 시작부터 허용합니다. 브라우저별 확대 후 이동 감촉·모든 Safari 버전의 이벤트 순서는 실기 확인이 필요하며, 지원되지 않는 브라우저에서 자체 확대를 제공하지는 않습니다.
- Goodnotes 참고: https://support.goodnotes.com/hc/en-us/articles/6554036735631-Zoom-pan-and-scroll-through-pages-in-Goodnotes . 원본은 두 손가락 핀치, 확대된 페이지의 한 손가락 이동, 설정된 방향의 페이지 스크롤을 설명합니다. Nib는 사용자의 명시 요청에 맞춰 두 손가락 페이지 넘김을 적용한 변형이며 Goodnotes와 완전히 같은 동작이라고 주장하지 않습니다.

## 화면 고정 · 한 손가락 긴 드래그로 페이지 추가 (2026.10.30.27)
- v26의 브라우저 전체 핀치와 두 손가락 페이지 넘김을 대체합니다. 앱 화면과 상단 메뉴는 고정하며, **두 손가락 이동·핀치는 노트 종이 안에서만** 처리합니다. 한 손가락으로 화면 전체를 끌거나 빈 여백으로 밀 수 없습니다.
- 기본 펜 모드(손가락 쓰기 끔) 또는 화면 이동 모드에서 **빈 종이를 왼쪽으로 길게 끈 뒤 놓으면 새 페이지 1장을 노트 맨 뒤에 추가하고 이동**합니다. 화면 폭에 따라 120~220px 이상, 가로 이동이 세로의 두 배 이상일 때 안내가 ‘놓으면 새 페이지 추가’로 바뀝니다. 거리를 되돌리면 취소할 수 있습니다. 짧은 쓸기·세로 이동·오른쪽 쓸기는 페이지를 추가하지 않습니다.
- 글·도형·원본 획 위에서 시작한 터치는 페이지 추가로 처리하지 않습니다. 기존 객체 이동, 손가락 필기, 지우개, 올가미, 그림 팔레트의 조작을 우선합니다. 두 손가락에서 하나가 남더라도 모두 떼기 전에는 새 획이나 페이지 추가로 전환하지 않습니다. 세 번째 손가락·터치 취소·페이지/화면 크기 변경·Pencil 입력은 미완성 추가 동작을 취소합니다.
- 기존 페이지 이동은 상단 **‹ / ›** 또는 페이지 목록을 사용합니다. **− / 배율 / ＋**로 종이 배율을 조절하고, 배율 버튼을 누르면 100%와 처음 위치로 돌아옵니다. 종이 배율은 50~400%이고 페이지 바깥으로 밀리지 않도록 이동 범위를 제한합니다. 마우스 휠은 종이 이동, Ctrl/⌘+휠은 종이 확대·축소이며 노트 보기 영역에 키보드 초점을 두고 화살표로 이동할 수도 있습니다.
- 이전 페이지 저장과 새 페이지 저장이 성공한 뒤에만 이동합니다. 저장 대기 중 반복 입력은 한 번만 처리하며, 저장 실패 시 기존 페이지와 내용이 유지됩니다. 페이지를 바꾸면 종이 배율·위치만 초기화합니다. 원본 SVG 좌표와 저장 데이터, PNG/인쇄 크기는 화면 배율에 따라 바뀌지 않습니다.
- 검증: 구문 검사, 707개 자동 테스트, 정적 빌드 통과. 로컬 Chromium의 1024×768·390×844 터치 에뮬레이션에서 한 손가락 화면 고정, 손을 뗄 때 한 장 추가, 두 손가락 확대·이동, 상단 메뉴/브라우저 배율 고정, 확대·이동 후 펜 좌표, 새로고침 후 저장 유지를 확인했습니다. **실제 iPad/Safari/Pencil 실기 검증은 아직 하지 않았습니다.**
- 브라우저 회귀 검사는 `npm run build` 후 Playwright가 있는 환경에서 `node scripts/verify-touch-browser.mjs`로 실행합니다. 별도 설치 경로는 `NIB_PLAYWRIGHT_MODULE`, Chromium 실행 파일 경로는 `NIB_CHROMIUM_PATH`로 지정할 수 있습니다. 검사는 임시 로컬 서버와 새 브라우저 저장소에서 실행하며 AI 호출이 없습니다.

## 이전·다음 페이지 순서대로 넘기기 (2026.10.30.28)
- v27에서 오른쪽 드래그가 동작하지 않고, 왼쪽 드래그가 현재 위치와 관계없이 맨 뒤에 새 페이지를 추가하던 문제를 수정했습니다. **빈 종이를 한 손가락으로 오른쪽으로 길게 끌고 놓으면 이전 페이지, 왼쪽으로 끌고 놓으면 바로 다음 페이지**로 이동합니다. 예를 들어 3페이지짜리 노트의 1페이지에서는 2페이지로 이동하며 총 페이지 수가 늘지 않습니다.
- **마지막 페이지에서 왼쪽으로 넘길 때만 새 페이지 한 장을 추가**합니다. 첫 페이지에서 오른쪽으로 넘기면 그대로 머무릅니다. 안내 문구는 이전 페이지·다음 페이지·새 페이지 추가를 구분합니다. 한 번의 드래그는 손을 뗄 때 한 번만 처리하며, 저장·전환 대기 중 반복 동작은 무시합니다. 저장 실패 시 현재 페이지와 내용이 유지됩니다.
- 화면·메뉴 고정, 두 손가락 종이 이동·확대, 필기·글·도형 조작 우선, 취소 조건과 거리 기준은 v27과 같습니다. 전체 1,000페이지 제한에 도달해도 기존 페이지 사이의 이동은 가능합니다.

## 같은 페이지에서 한 손가락 세로 이동 (2026.10.30.29)
- **한 손가락으로 위아래로 끌면 현재 종이만 세로로 이동**합니다. 화면과 상단 메뉴는 고정하고 종이의 배율과 가로 위치는 유지합니다. 종이 위·아래 끝에서는 멈추며, 종이가 화면 안에 전부 들어오면 세로 이동하지 않습니다.
- 처음 분명해진 가로·세로 방향을 손을 뗄 때까지 유지합니다. 세로로 움직이다 옆으로 꺾어도 페이지가 바뀌거나 추가되지 않습니다. 좌우로 길게 넘기는 이전·다음 이동과 마지막 페이지에서만 한 장 추가하는 동작은 v28과 같습니다. 두 손가락 종이 이동·확대도 유지합니다.
- 기본 펜 모드에서 손가락 쓰기를 끄면 빈 종이와 원본 필기 위에서 세로 이동할 수 있습니다. 변환 글·도형 위에서는 기존 객체 조작을 우선합니다. **화면 이동** 모드에서는 글·도형 위에서도 종이를 위아래로 움직일 수 있습니다. 손가락 쓰기·지우개·올가미·그림 도구 사용 중에는 해당 편집 동작을 유지하며 Pencil·손바닥 방어도 그대로입니다.

## 지우개로 그림·표 삭제 (2026.10.30.30)
- 원형 지우개가 원본 필기뿐 아니라 직선·화살표·사각형·타원·삼각형·마름모·표에도 적용됩니다. **필기는 닿은 부분을 자르고, 그림·표는 닿은 객체 전체를 삭제**합니다. 그림 안 글과 표의 셀 내용도 함께 삭제되며, 지우개 선택 안내에 이 차이를 표시합니다. 독립된 변환 글·키보드 글 객체는 기존대로 유지합니다.
- 원형 지우개의 크기와 두 입력점 사이 경로를 모두 검사하므로 빠르게 쓸어도 중간의 그림·표를 놓치지 않습니다. 닫힌 도형은 내부도 삭제 대상으로 처리합니다. 직선·화살표는 실제 선·화살촉, 타원·삼각형·마름모는 해당 형상을 검사해 경계 상자의 빈 모서리만 스쳤을 때는 삭제하지 않습니다.
- 한 번 드래그해 지운 필기·그림·표는 한 번의 실행 취소로 모두 복원하며 다시 실행도 가능합니다. 아무것도 닿지 않으면 실행 취소 기록을 추가하지 않습니다. 확대·이동된 종이에서도 원본 좌표로 처리하고, 삭제 상태는 기존 저장 경로로 유지합니다.
- 검증: 구문 검사, 741개 자동 테스트, 빌드 통과. Chromium 1024×768·390×844에서 실제 도구로 타원과 글이 든 표를 만든 뒤, 확대 상태에서 지우개로 함께 삭제하고 한 번의 실행 취소로 둘 다 복원한 다음 다시 실행·새로고침 후 삭제 유지까지 확인했습니다. 기존 한 손가락 세로 이동, 좌우 페이지 넘김, 두 손가락 확대 검증도 통과했습니다. 실제 iPad/Safari 실기 검증은 아직 하지 않았습니다.
